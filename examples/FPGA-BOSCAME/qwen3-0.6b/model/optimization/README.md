# AME v0.5 optimization checks

`dequant_ab_launch.c` links the original and optimized **Triton/Buddy-generated**
kernel objects and the adapters generated by the normal exporter. Only symbols
are renamed; the adapters retain their original descriptor/grid behavior. The C
arithmetic is the independent numerical oracle, never a replacement kernel.

The test covers INT32 extrema, integers around the FP32 rounding boundary
`2^24`, positive finite non-power-of-two scales, explicit FP32 operation order,
three changed-input repetitions, alternating variant order, nonzero descriptor
offsets, input preservation, and input/output canaries. Every result is checked
bitwise. Max/mean absolute error are also reported as IEEE double hex bits. The
same harness supports row/tail shapes by linking matching specialized objects.

From the repository root, after the normal Triton builder has produced the two
case directories:

```bash
MODEL=examples/FPGA-BOSCAME/qwen3-0.6b/model
python3 "$MODEL/optimization/build_dequant_ab.py" \
  --baseline "$MODEL/build/ame-v05/baseline/dequantize_1x151936" \
  --optimized "$MODEL/build/ame-v05/rvv/dequantize_1x151936"
# Repeat with --host to validate the same lowered LLVM IR on the host.
```

The inputs must each contain `frontend.json`, `adapter.c`, `nr/manifest.json`, `nr/kernel.o`,
`nr/adapter.o`, and (for host checks) `nr/kernel.ll`. Shapes and descriptor types
and exact production adapter/grid behavior are checked. Native/frontend manifest
hashes must agree with the TTIR, linalg, LLVM IR, and adapter sources. The builder
snapshots the original objects and available IR,
records hashes, renames both raw symbols and adapter symbols on copies, reuses
`common/nr/nr.mk`, uses LLD 20 or newer, and audits the final ELF. It does not
modify the input directories. Default output is under `model/build/ame-v05/`.
An existing nonempty output directory is rejected: supply a fresh `--output`
for each rebuild, so changing repeat counts/configuration cannot reuse stale
objects or overwrite previous evidence.

Only the coordinating agent should start board jobs, after checking the existing
runner lock. The usual runner command is:

```bash
examples/FPGA-BOSCAME/fpga_run.sh \
  "$MODEL/build/ame-v05/dequant-ab-1x151936/dequant-ab.bin" \
  --fpga=5 --capture-seconds=120 --completion-marker='[nr] RA returned:'
python3 "$MODEL/optimization/check_dequant_ab.py" /path/to/uart.raw.log \
  --platform fpga \
  --manifest "$MODEL/build/ame-v05/dequant-ab-1x151936/manifest.json" \
  --output "$MODEL/build/ame-v05/dequant-ab-1x151936/result.json"
```

For a local run use `--platform host` and the `-host/output.log` and
`-host/manifest.json` files. Host timings are `clock()` ticks, **not FPGA cycles**.
Board timings include the production adapter/grid overhead, and exclude data
initialization, oracle comparisons, and UART output. No hardware fence is added
to the existing RVV-only dequantization path. Successful checking requires every
sample/pair, all-zero errors, final completion, and (on FPGA) NR return PASS.

To preserve compact evidence after a successful board run:

```bash
python3 "$MODEL/optimization/archive_dequant_ab.py" \
  --run examples/FPGA-BOSCAME/build/fpga-runs/run-RUN_ID \
  --build "$MODEL/build/ame-v05/dequant-ab-1x151936" \
  --output "$MODEL/validation/board/ame-v05/dequant-1x151936"
```

The archiver requires the binary, build manifest, and runner upload hash to
agree; DDR readback must match. It rechecks recorded input hashes and ABI/grid
contracts, then copies only compact manifests, ELF audit, UART, and the strict
numerical/timing report. Binaries and full IR remain in the immutable build
directory. Existing nonempty archives are rejected.

This directory implements the first optimization test (dequantization). AME
register encoding, N32/N64 tiling, and synchronization experiments must have
separate evidence; a dequantization PASS does not validate those changes.

The AME register-encoding A/B harness uses the same builder with INT8 linear
cases. It checks the production `C += A@B` contract with a compact independent
int64 oracle (32 deterministic B row templates), all output elements, nonzero C
initialization, all A bytes, sampled B bytes and canaries. It reports the kernel
call plus post-`ame_fence()` time separately from pre-sync setup:

```bash
python3 "$MODEL/optimization/build_ame_ab.py" \
  --baseline "$MODEL/build/ame-v05/ame-fixed/matmul_1x151936x1024" \
  --optimized "$MODEL/build/ame-v05/ame-direct/matmul_1x151936x1024"
# Add --full-input-scan when the extra B-memory validation is worthwhile.
python3 "$MODEL/optimization/build_ame_ab.py" \
  --baseline "$MODEL/build/ame-v05/ame-fixed/matmul_1x151936x1024" \
  --optimized "$MODEL/build/ame-v05/ame-direct/matmul_1x151936x1024" --host
```

The `--host` image is a control compiled from the same Triton-generated host
LLVM lowering; it does not execute AME instructions. The NR image links the
actual AME-lowered objects and is the only image suitable for board timing.
`archive_ame_ab.py` applies the same strict board evidence checks as the
dequantization archiver.

## Relink a controlled 1-layer model variant

`build_model_variant.py` reuses the validated `review-native-1l` graph, graph
adapters, real checkpoint weight segment, and independent NR reference. It
restores the exact 46 kernel builds from the baseline archive's objects and
hash-checked evidence, applies only explicit `--replace-case` choices through
`kernel_build_overlay.py`, and runs `archive_kernels.py` for that same case list.
It then builds a new image with the common NR runtime and prepares its DDR load
plan. It never rebuilds shared kernel directories or starts an FPGA task.

This helper deliberately accepts **only one layer, context capacity 512, the raw
prompt `What is France?`, 16-token prefill, and eight successive decode steps**.
The raw text is tokenized and decoded on the board. Kernel profiling is off;
the selected intermediate probes and progress remain enabled. Output/reference
semantics and graph ordering are retained when changing an internal kernel
implementation or blocking choice. A built image is not a board PASS.

Run from the repository root with the `boscame` environment active:

```bash
MODEL=examples/FPGA-BOSCAME/qwen3-0.6b/model
STAGE="$MODEL/build/review-native-1l"
VARIANT="$MODEL/build/ame-v05/model-rvv-dequant-example"
python3 -B "$MODEL/optimization/build_model_variant.py" \
  --stage "$STAGE" \
  --replace-case "$MODEL/build/ame-v05/rvv/dequantize_1x151936" \
  --weights "$MODEL/build/board/w8a8-1l-run/weights-w8a8.bin" \
  --weight-manifest "$MODEL/build/board/w8a8-1l-run/w8a8-segment.json" \
  --tokenizer "$MODEL/build/tokenizer.bin" \
  --intermediate-layout "$MODEL/build/import/probe-1layer/weight-layout.json" \
  --output "$VARIANT" --linker "$(command -v ld.lld-20)"
```

Repeat `--replace-case` for each kernel being tested. Add `--dry-run` to validate
baseline files and print the complete commands without creating output or
building. All resource paths are explicit arguments; LLD must be version 20 or
newer. Existing output directories, including empty ones and broken symlinks,
are refused. Failed builds retain a `FAILED_DO_NOT_DEPLOY` record and logs;
choose a new output directory for the next attempt. `variant.json` records
commands, inputs, baseline archive hash, replacements, and the resulting hashes.

The output contains `model-lib/`, `image/`, and `prepared/`. Directory symlinks
for the preserved graph/adapters/reference resolve back to the baseline so
`archive_model_run.py --build "$VARIANT"` can validate the exact original
build-time inputs. Keep the baseline stage and replacement case directories
unchanged while building and archiving. The normal archive is self-contained
for its copied source/IR/object evidence; large resources remain local.

After the individual kernel has passed board validation, the coordinating
runner owner can execute this model and then archive its strict checks:

```bash
"$MODEL/tools/run_model.sh" "$VARIANT/prepared" \
  --fpga=5 --capture-seconds=900
# Use the actual completed runner directory printed by run_model.sh.
RUN=examples/FPGA-BOSCAME/build/fpga-runs/run-ACTUAL_ID
python3 -B "$MODEL/tools/archive_model_run.py" \
  --run "$RUN" --build "$VARIANT" \
  --image-dir "$VARIANT/image" --prepared-dir "$VARIANT/prepared" \
  --host-graph "$STAGE/host-run/arrays.npz" \
  --quant-reference "$STAGE/quant-nr-trace/arrays.npz" \
  --reference-metadata "$STAGE/quant-nr-trace/quant-reference.json" \
  --assets "$MODEL/assets/official" \
  --layers 1 --prefill 16 --steps 8 \
  --output "$MODEL/validation/board/ame-v05/model-rvv-dequant-example"
```

Set `--assets` to the directory containing the official tokenizer files used
for this checkpoint. Require the numerical, intermediate, full-logits/KV and
fixed-text checks to pass. The host graph and quantized references are validation
oracles; they are not involved in board inference. A successful one-layer
experiment does not validate the complete 28-layer model.

## Reproduce the combined 18-kernel variant

First prepare the official assets, checkpoint, imported one-layer graph, and
validated baseline stage following [the model instructions](../README.md).
Those prerequisites supply `review-native-1l`, the weight segment, tokenizer
blob, and independent reference used below. Activate the `boscame` environment
and rebuild Buddy if the lowering implementation changed.

Select the exact model shapes from the validated archive's semantic families.
Do not glob all `matmul_*` directories: those also contain unrelated tail and
stress cases. These commands compile all 18 kernels **from their Triton source**
through triton-riscv, Buddy lowering, assembly restriction, object compilation,
and ELF audit into fresh directories, then link a fresh model variant:

```bash
MODEL=examples/FPGA-BOSCAME/qwen3-0.6b/model
STAGE="$MODEL/build/review-native-1l"
VARIANT="$MODEL/build/ame-v05/model-combined-reproduction"
REPLAY="$MODEL/build/ame-v05/source-reproduction"
[[ ! -e "$REPLAY" && ! -L "$REPLAY" ]] || exit 1
mkdir -p "$REPLAY"
source examples/FPGA-BOSCAME/common/triton/triton-env.sh
mapfile -t SELECTED_CASES < <(python3 - "$STAGE/model-lib/archive.json" <<'PY'
import json, sys
records = json.load(open(sys.argv[1]))['cases']
selected = [r for r in records if r['frontend']['family'] in ('matmul_i8', 'dequantization')]
assert sum(r['frontend']['family'] == 'matmul_i8' for r in selected) == 11
assert sum(r['frontend']['family'] == 'dequantization' for r in selected) == 7
for record in sorted(selected, key=lambda r: r['case']):
    root = 'ame-n64-coalesce' if record['frontend']['family'] == 'matmul_i8' else 'rvv'
    print(root + '/' + record['case'])
PY
)
[[ ${#SELECTED_CASES[@]} == 18 ]] || exit 1
REPLACEMENTS=()
AME_CASES=()
DEQUANT_CASES=()
for case in "${SELECTED_CASES[@]}"; do
  REPLACEMENTS+=(--replace-case "$REPLAY/$case")
  case "$case" in
    ame-n64-coalesce/*) AME_CASES+=(--case "${case#*/}");;
    rvv/*) DEQUANT_CASES+=(--case "${case#*/}");;
    *) exit 1;;
  esac
done
QWEN_TRITON_AME_N=64 \
QWEN_TRITON_BUILD_ROOT="$PWD/$REPLAY/ame-n64-coalesce" \
QWEN_MAKE_FLAGS='RISCV_LD=/usr/bin/ld.lld-20 AME_GPR_MODE=direct NR_COALESCE_FENCES=1' \
  python3 -B "$MODEL/../triton/build.py" "${AME_CASES[@]}" --jobs 2
QWEN_TRITON_DEQUANT=rvv \
QWEN_TRITON_BUILD_ROOT="$PWD/$REPLAY/rvv" \
QWEN_MAKE_FLAGS='RISCV_LD=/usr/bin/ld.lld-20 AME_GPR_MODE=fixed NR_COALESCE_FENCES=0' \
  python3 -B "$MODEL/../triton/build.py" "${DEQUANT_CASES[@]}" --jobs 2
python3 -B "$MODEL/optimization/build_model_variant.py" \
  --stage "$STAGE" "${REPLACEMENTS[@]}" \
  --weights "$MODEL/build/board/w8a8-1l-run/weights-w8a8.bin" \
  --weight-manifest "$MODEL/build/board/w8a8-1l-run/w8a8-segment.json" \
  --tokenizer "$MODEL/build/tokenizer.bin" \
  --intermediate-layout "$MODEL/build/import/probe-1layer/weight-layout.json" \
  --output "$VARIANT" --linker "$(command -v ld.lld-20)"
```

The AME and dequantization build directories are separate so no variant can
replace another variant's source/object evidence. The dequantization builder
also executes the actual vector-lowered LLVM on the host. The model run and
strict model archive commands above apply to this new `$VARIANT`; all execution
still requires the coordinating agent to serialize FPGA access.

The source-controlled suite wrapper reproduces a single image containing those
18 independent parent kernel oracles. It reads the model variant's actual
`replace_cases`, verifies them against the immutable model archive, snapshots
the 36 kernel/adapter objects and their source/configuration evidence, and invokes
the existing Triton suite builder. Kernel compilation is not repeated; launchers
and the shared NR runtime are compiled into a fresh output. Existing case trees
and symlink targets are unchanged. `--dry-run` validates and prints the plan
without building or creating output:

```bash
SUITE_BUILD="$MODEL/build/ame-v05/selected-suite-reproduction"
python3 -B "$MODEL/optimization/build_selected_suite.py" \
  --variant "$VARIANT/variant.json" --output "$SUITE_BUILD" \
  --linker "$(command -v ld.lld-20)"
SUITE="$SUITE_BUILD/kernels/suite-optimized-model-kernels"
# After the coordinating runner has completed this suite.bin on FPGA:
python3 -B "$MODEL/optimization/archive_selected_suite.py" \
  --run examples/FPGA-BOSCAME/build/fpga-runs/run-ACTUAL_ID \
  --suite "$SUITE" \
  --output "$MODEL/validation/board/ame-v05/optimized-model-kernels-reproduction"
```

The strict archiver requires 18 ordered case starts, 18 zero-error checks, the
suite PASS, NR return PASS, matching UART length, matching image/upload hashes,
DDR readback, and unchanged kernel/runtime/launcher object hashes. The source
configurations of reused objects are recorded individually; the suite link
configuration cannot change the AME mode of an already compiled object.
