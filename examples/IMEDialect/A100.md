# K3 / SpacemiT A100 IME

The A100 path uses the LLVM revision pinned by Buddy's `llvm` submodule. No
changes to the embedded or external LLVM sources are needed.

## SSA tile interface

`ime.intr.*` operations take scalable vector values and return a new accumulator
or packed vector. A vector describes a register-sized value; it does not name
a physical register. LLVM allocates the registers, ties dot results to their
accumulators, and restricts HP/SP parameter vectors to v0/v1.

The A100 overloads require **VLEN=1024**, or `vscale=16`. A single vector register
then holds 128 bytes. `-mcpu=spacemit-a100` enables `XSMTVDotII` and `zvl1024b`,
but the latter only guarantees a minimum VLEN. Before executing a kernel, the
runtime must select an A100 core and check `vlenb == 128`.

| Operation | Accumulator / result | A | Transposed B | Parameters |
| --- | --- | --- | --- | --- |
| `ime.intr.vmadot{,u,su,us}` | `vector<[4]xi32>` | `vector<[8]xi8>` | `vector<[8]xi8>` | none |
| `ime.intr.vmadot{,u,su,us}.hp` | `vector<[4]xf16>` | `vector<[8]xi8>` | `vector<[8]xi8>` | `vector<[4]xf16>`, `group=0..7` |
| `ime.intr.vmadot{,u,su,us}.sp` | `vector<[4]xi32>` | `vector<[16]xi8>` | `vector<[8]xi8>` | `vector<[8]xi8>`, `group=0..3` |
| `ime.intr.vfmadot` | `vector<[4]xf32>` | `vector<[4]xf16>` | `vector<[4]xf16>` | none |

The `u`, `su` and `us` suffixes select unsigned/unsigned, signed/unsigned and
unsigned/signed input interpretation. SSA integer vectors remain signless.
HP computes an int8 8x16 dot, scales each output column by
`scales[group*8 + column]`, and accumulates into FP16. Its result occupies one
register. SP is a **4:2 sparse int8** dot with int32 accumulation; it is not an
FP32 operation. Its A input occupies a register pair.

FP16 dot uses `smt.vfwmadot` and accumulates into FP32. Both it and HP require
the platform runtime to establish `MCPM.BF16=0`. The intrinsics do not switch
this CSR. The current board tests validate its FP16 default; they do not
implement a portable mode-switch API.

For example, a dot chain stays in SSA until the final store:

```mlir
llvm.func @dot(%cp: !llvm.ptr, %ap: !llvm.ptr, %bp: !llvm.ptr) {
  %c = llvm.load %cp {alignment = 4 : i64} : !llvm.ptr -> vector<[4]xi32>
  %a = llvm.load %ap {alignment = 1 : i64} : !llvm.ptr -> vector<[8]xi8>
  %b = llvm.load %bp {alignment = 1 : i64} : !llvm.ptr -> vector<[8]xi8>
  %r = "ime.intr.vmadot"(%c, %a, %b) : (vector<[4]xi32>, vector<[8]xi8>, vector<[8]xi8>) -> vector<[4]xi32>
  %r2 = "ime.intr.vmadot"(%r, %a, %b) : (vector<[4]xi32>, vector<[8]xi8>, vector<[8]xi8>) -> vector<[4]xi32>
  llvm.store %r2, %cp {alignment = 4 : i64} : vector<[4]xi32>, !llvm.ptr
  llvm.return
}
```

Ordinary LLVM loads/stores of these vectors select whole-register RVV memory
instructions. They do not require a separate load VTYPE between consecutive
dots. Higher-level producers can also use `vector.load` / `vector.store` and
the standard vector-to-LLVM conversion.

## Pack and unpack

All six layout operations take two SSA vectors and a `block` i32 attribute in
0..3. Their complete source registers are read independently of VL.

| Operation | Input type | Result type | Meaning |
| --- | --- | --- | --- |
| `vpack`, `vupack` | `vector<[64/SEW]xiSEW>` | `vector<[128/SEW]xiSEW>` | Interleave / de-interleave blocks; SEW=8,16,32,64 |
| `vnpack`, `vnspack` | `vector<[32/SEW]xi(2*SEW)>` | `vector<[64/SEW]xiSEW>` | Truncate / signed-saturate and interleave; SEW=8,16,32 |
| `vnpack4`, `vnspack4` | `vector<[8]xi8>` | `vector<[8]xi8>` | Truncate / signed-saturate bytes to packed nibbles, low nibble first |

These are the operations `ime.intr.vpack`, etc. For example:

```mlir
%r = "ime.intr.vnspack4"(%a, %b) {block = 0 : i32} : (vector<[8]xi8>, vector<[8]xi8>) -> vector<[8]xi8>
```

For wide pack/upack, `block` selects SEW, 128, 256 or 512-bit blocks. For the
narrowing operations it selects 32, 64, 128 or 256 bits of narrowed output
from each source. Saturation does not use `vxrm` or update `vxsat`.
`vupack` rearranges elements; it does **not** sign-extend int4 to int8.

## Memref and Linalg lowering

The existing `ime.vmadot{,u,su,us}` and `ime.vfmadot` memref syntax is preserved.
Use `-lower-ime="target=k3"` to select the A100 bridge. It expects C[M,N],
A[M,K], and **packed B[N,K]**. Integer M,N are at most 8 and K at most 16;
FP16 K is at most 8. Shapes must be static and nonempty.

Complete contiguous signed int8 tiles use direct whole-register loads/stores,
including the descriptor offset. Partial or strided tiles are zero-padded
through bounded scratch storage, and only the active C elements are written
back. FP16 memref C retains its existing f16 API: it widens to f32 for the
instruction and rounds back to f16 after each dot. Use the SSA interface to
retain a native FP32 accumulator across a longer FP16 dot chain.

`-lower-linalg-to-ime="target=k3"` selects 8x16x8 integer tiles and 8x8x8 FP16
tiles for static `linalg.matmul`, recognized FP16 matmul generics and batched matmul
with transposed B indexing maps. The named matmul path transposes B and handles
boundary tiles. Automatic HP/SP recognition, K3 sliding windows and convolution
lowering are deferred. The default `target=generic` keeps the K1 path.

The memref bridge prioritizes correctness for existing callers. Native SSA
microkernels avoid its scratch copies and repeated f16 accumulator rounding.

## Reproduce the hardware regressions

From this directory, using a built Buddy toolchain:

```sh
make a100-ssa-object k3-dot-object
ssh k3-005 'mkdir -p /tmp/buddy-ime'
scp ../../build/ime-a100/a100-kernels.{o,h} ../../build/ime-a100/k3-dot.o \
  runtime_a100_tests.c runtime_k3_dot_test.c runtime_k3_runner.c k3-005:/tmp/buddy-ime/
```

On the board:

```sh
cd /tmp/buddy-ime
gcc -O2 -march=rv64gc_zfh runtime_a100_tests.c runtime_k3_runner.c a100-kernels.o -o a100-tests
./a100-tests
gcc -O2 -march=rv64gc_zfh runtime_k3_dot_test.c runtime_k3_runner.c k3-dot.o -o k3-dot-tests
./k3-dot-tests
```

The supplied runner uses the tested K3 firmware's `/proc/set_ai_thread` interface
and CPU 8; adapt this platform setup for other firmware. It checks VLEN before
entering either generated kernel set. Keep the C runner compiled for the scalar
baseline ISA so no A100-specific code executes before affinity is established.

The SSA regression covers all 21 non-window instructions: 117 type/immediate
combinations and 1695 scalar-reference cases, including all `vxrm`/`vxsat`
states for packs and invalid sparse masks. The memref regression covers signed
and unsigned inputs, nonzero offsets, strides, boundaries, Linalg matmul and a
20000-iteration dot loop. Compilation and verifier regressions also run under
`ninja check-buddy`; hardware execution requires an A100 board.
